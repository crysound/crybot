## 情况
第 3 轮改动通过了独立复审，但 GitHub Actions 的 CI（run 43593397669，提交 cb81f81d）里有 5 个测试文件只在本分支失败，main 上同一批是绿的。这些都由本任务的改动引起，要全部修好。CI 的失败摘录附在本文末尾。

## 必改
1. `server/chat-notices.test.ts`：新增的 3 条提示 `chat.notice.computerWakeFailed`、`chat.notice.previousComputerWakeFailed`、`chat.notice.wakingComputer` 没进目录（catalog）。照这个测试要求的方式登记（看测试怎么取目录，把这三条按现有提示的做法补齐，含语言包）。
2. `src/locales/server-lines.test.ts`：`server/local-vm-resume.ts:25` 把英文句子直接写在代码里（"The computer could not wake…"），经 `server/index.ts:8163` 的状态行给人看。按测试注释的要求，改成走 `en.json` 的 `server.` 键，并按 `lineLanguage` 给出对应语言；其他语言包按仓库现有做法补齐（看 `src/locales/*.json` 里同类键怎么处理）。
3. `server/cloud-computer-slow-start.e2e.test.ts` 2 例：云电脑启动被限额拒绝、或启动失败时，等在上面的调用应该拿到「The cloud computer could not be started…」那句原因，现在拿到的是「This turn no longer has this computer…」。查清是本任务哪一处改动（冷却、合并请求、readinessOnly、后台唤醒）改变了失败原因的传递，恢复 main 上的行为。
4. `server/group-local-vm.e2e.test.ts` 4 例：
   - chat selection 选中后才启动/开通云电脑（missing-auto），返回里 `surface: 'cloud'` 对不上；
   - 就绪 claim 失败后要释放，让机器人和房间能再跑（现在等待超时）；
   - Auto VM 的 eager 等待在占用者停下后要恢复，`busy: false`；
   - 懒加载 claim 被拒后以终止错误结束本轮（issues #1361 F1、#1369），对象不相等。
   逐条查清是本任务哪处改动引起的，修到和 main 行为一致（本任务新增的「唤醒提示」「后台唤醒」「冷却」不能改变这些既有语义）。
5. `evals/evals.test.ts` 的 `lazy-claim-rejection`：`busy=false for auto` 等了 20 秒仍是 true。多半和第 4 条最后一例同源，修好后确认。
