## 必改：宿主侧解包要真正拒绝越界、软链接逃逸、硬链接
位置：`server/screen-profile-files.ts:88-106`（`extractScreenProfile`），第 92 行 `preservePaths: true`，第 94-101 行 filter。

复审员把该函数原样复制出来，用构造的归档实跑，确认以下 4 种情况都没拦住：
1. 条目 `./a/../../ESCAPED-dotdot` 写到了解包目录之外。filter 只拦以 `/` 或 `../` 开头的路径。
2. 先放软链接 `./x`（指向外部目录），再放 `./x/ESCAPED-symlink`，文件写进了外部目录。软链接集合存的是 `posix.normalize` 后的 `x`，比对时用的却是原始的 `./x/...`，永远匹配不上。
3. 硬链接 `./leak` 指向宿主上的绝对路径，暂存区里出现了与宿主文件同 inode 的链接，随后被 `transferProfile` 当作普通文件写进屏。
4. 条目是绝对路径 `/ABS-escape` 时，filter 里 throw 的错误没有被 pipeline 的 Promise 接住，变成未捕获异常，node 进程直接退出。

安全审查（中危）另外指出：filter 只把连续两个反斜杠换成 `/`，单个 `\` 不处理。在 Windows 宿主上，`./..\..\..\payload` 会被 node-tar 规范成 `../`，从而越界。

改法：
- filter 先把 `\` 视为非法：条目路径或软链接目标里只要含 `\` 就拒绝。然后做 `posix.normalize`，并拒绝以下情况：绝对路径、任一段等于 `..`、规范化后为空或越出根。软链接前缀比对改用同一规范化形式；前缀命中时，后续条目一律拒绝。
- 条目类型只放行 File、Directory、SymbolicLink。`Link`（硬链接）、设备文件、FIFO 等一律拒绝。打包端加 `--hard-dereference`，让正常资料不出现硬链接（这是打包端唯一允许的改动）。
- 保留 `preservePaths: true`：r2 第 4 条要求绝对目标的软链接（如 `/usr/bin/python3`）原样保留，去掉它会剥掉开头的 `/`。所有路径防护由上面的 filter 自己做。
- filter 里不要 throw：记下第一个错误并返回 false，解包结束后（或主动让 extractor 以 error 结束）reject，保证错误一定走 Promise，进程不会崩。被拒绝的归档按抢救失败处理，保留 rescue-pending，不能返回 `"none"` 让重建继续删旧容器。
- 补测试：用构造的归档（可用 node-tar 或手写 tar 头生成）覆盖上面 4 种情况，再加 `./..\..\x`（反斜杠）和设备文件条目两种。断言解包目录外没有新文件、不产生硬链接、进程不崩，rescue 返回 reject，且 pending 标记保留。
