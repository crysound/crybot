## 必改
1. Actions 的 iOS 编译失败（exit 65）：`.github/workflows/mobile.yml` 的 CryBot 编译命令带了 `-sdk iphonesimulator`，导致内嵌的手表 target 被按 iOS SDK 编译，actool 报 `CryBotWatch/Assets.xcassets ... AppIcon did not have any applicable content`。去掉 CryBot 那一步的 `-sdk iphonesimulator`，只保留 `-destination 'generic/platform=iOS Simulator'`，让依赖按各自平台编译；`mobile/ios/README.md` 里同一条命令一起改。手表单独编译那步同理，检查是否也该只用 `-destination 'generic/platform=watchOS Simulator'`。CryBotWatchTests 那步用 `-destination` 指定模拟器即可，同样不要多余的 `-sdk`。内嵌产物检查路径要和不带 `-sdk` 后的实际产物路径一致（仍是 `Debug-iphonesimulator/Cry Bot.app/Watch/CryBotWatch.app`，自己核对 PRODUCT_NAME）。Contents.json 不用动。

## 本轮一起做的建议
2. `Shared/WatchContract.swift` 的 `WatchBot.threadId` 改成可选：服务端某些场景会删掉 bot 的 threadId。解码 bot 列表时逐个宽容：单个 bot 解码失败或缺 threadId 时跳过或标为不可进入会话，不能让整个列表失败。补单元测试。
3. `CryBotWatch/APIClient.swift` 列表请求 `/api/bots?messages=20` 改成 `messages=5`（会话页自己拉消息）。
4. `Shared/WatchContract.swift` 去掉 `cry_session_<端口>_` 按公网端口优先的逻辑（服务端 cookie 名用的是监听端口，公网 URL 端口不对应）：多个 `cry_session_*` 时直接取过期时间最晚的。删掉/改写 `testPrefersCurrentPortWhenMultipleSessionsShareHost`，改为测「取过期时间最晚的那个」。
5. `CryBotWatch/Session.swift` Keychain 可访问性改为 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`（令牌不随备份迁到别的设备），README/报告里同步说明。
6. 403 处理：只把以下情况判为登录过期——401；302/303/307 重定向；以及响应体不是服务端 JSON 错误（即 Cloudflare 边缘返回的 403，服务端 403 的响应体是带 `error` 字段的 JSON）。服务端带 JSON `error` 的 403 显示为「请求失败」（新文案，中英文都加），不清会话、不停止轮询。补单元测试覆盖两种 403。
7. `CryBotWatchApp.swift` 中 `BotListView` 的 `private let api = APIClient()` 会随视图重建新建 URLSession：改成共享实例或放进 ObservableObject/@State，会话页同理检查。
8. `latestReply` 优先取最后一条 `role == "bot"` 且 `kind == "text"` 的消息，没有才退回最后一条 bot 消息。补测试。
9. Actions 挑模拟器脚本按 runtime 版本号数值排序（`iOS-18-10` 应排在 `iOS-18-5` 前），不要按字符串字典序。
