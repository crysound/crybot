## 协调者定的规则（代码文件里的域名，取代 r3 第 5 条的做法）
代码文件（README 里列的扩展名，sh/bash/zsh/fish 除外）里，一个域名形状的文本只在下面三种情况才算主机：
1. 前面是 `://`，或者是 `@` 后面的主机部分（现状不变）。
2. 引号里整段就是一个主机名（`isWholeStringHost`），**并且**末段 TLD 不是常见文件扩展名（至少 md、sh、py、rs、js、ts、json、yml、yaml、txt、zip、mov、mp4、png、jpg、gz、tar、log、csv、html、css、swift、kt、java、go、rb、pl，自己补全写进 README），**并且**不是 `t(`/`i18n.t(` 这类翻译函数的第一个参数。私有后缀（internal、corp、lan、local、home、private、intranet、localdomain、home.arpa）在引号里一律算。 <!-- public-scan: allow domain -->
3. 不加引号的值**一律不算**，不管前面有没有 `host`/`hostname`/`baseURL` 这类上下文词——代码里没加引号的就是表达式。
shell 文件和 md/txt/yml/yaml/json 等正文保持现状（shell 的 `DOMAIN=x.y.internal` 不加引号也要报）。 <!-- public-scan: allow domain -->
名单（denylist）哈希不受这条影响：全部原始匹配照旧算，内部名靠名单兜底。
