## 必改（中危）：名单无盐 SHA-256 公开，可离线穷举还原
内部名字是低熵词（2–4 字中文人名、短标识符），无盐 SHA-256 提交到公开仓库等于泄露名单。改为：
1. `denylist.sha256` 改名为 `denylist.hmac`，每行是 `HMAC-SHA256(key, 小写词)` 的 64 位十六进制。key 从环境变量 `PUBLIC_SCAN_DENYLIST_KEY` 读（Actions secret 同名），代码和日志绝不输出 key。
2. 有 key：照旧检查 denylist 规则。没有 key（fork PR、本地未配）：跳过 denylist 规则并输出一行固定提示 `denylist: skipped (no key)`，其他规则照常；退出码不因跳过而变红。名单文件格式错误仍按配置错误退出。
3. 工作流 `public-scan.yml`：scan 步骤加 `env: PUBLIC_SCAN_DENYLIST_KEY: ${{ secrets.PUBLIC_SCAN_DENYLIST_KEY }}`（仍是 pull_request 事件，不改成 pull_request_target，不新增权限）。
4. 提供生成名单行的小工具 `scripts/public-scan/hmac-word.mjs`：从标准输入逐行读词，用环境变量里的 key 输出 HMAC 行；不接受 key 作为命令行参数。
5. 测试：有 key 时命中；错 key 不命中；无 key 时 denylist 跳过且有提示、其他规则仍报；日志不含 key。现有 denylist 测试改用测试 key 生成的 HMAC。仓库里提交的 `denylist.hmac` 只能含注释和一个用测试 key 之外的占位行，或者只有注释（协调者稍后用真实 key 填）。
6. README 的 denylist 条款同步改写，说明 fork PR 不跑名单检查、协调者本地 pre-push 可配 key 跑。

## 顺手修（低危，改动小）
- 低 3：输出行加固定前缀，保证行首永远不是 `::`（例如 `public-scan: <路径>:<行>: <规则>`），补一个以 `::warning::` 开头的文件名用例。
- 低 4：HEAD 文件含 NUL 被整份跳过时，报一条新规则 `binary-skip`（只报路径，退出码变红），真正的二进制扩展名列表里的文件仍静默跳过；可用 `public-scan: allow binary-skip` 豁免。更新 README 的规则名列表。
