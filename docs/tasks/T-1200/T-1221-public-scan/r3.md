2. **内部域名漏报。**
   - 私有后缀不在 IANA 表里也要识别：`internal`、`corp`、`lan`、`local`、`home`、`private`、`intranet`、`localdomain`（`home.arpa` 保持能报）。和代码成员名会撞的（如 `local`、`home`、`private`）仍要求主机上下文。 <!-- public-scan: allow domain -->
   - 「整个字符串字面量就是一个主机名」按引号内的内容判断，不看整行：`const API = "api.corp.dev";`、`{ endpoint: "api.corp.live" }` 要报。 <!-- public-scan: allow domain -->
   - 主机上下文词不要用 `\b` 卡死，要能匹配 `hostname:`、`baseURL =`、`apiUrl`、`endpoint`、`server`、`domain`、`host` 这些写法（大小写不敏感，允许后接 `:`、`=`、引号）。
   - `net` 从易混表移出（它不像代码成员名那样常见；如果移出后历史误报明显上升，在报告里给数字再决定）。
3. **名单分词缺口。**
   - 后缀哈希对域名正则的全部原始匹配都算，不经过候选/上下文过滤：没有上下文的 `ci.<词>.dev`、`wiki.<词>.net/page`、私有 TLD `api.<词>.internal` 只要名单命中就报。
   - 标识符整词（`[A-Za-z0-9_.-]+` 整串）也推入哈希，再推拆开的子词：名单里登记 `acme-ops`、`acme_bot` 这种带分隔符的整词也要命中。
   - 测试补：无上下文的 `.dev`/`.net` 子域名、私有 TLD、带分隔符整词三种，全部断言输出不含原文。
4. **路径会把名单原文打进日志。** 路径本身命中名单时，输出不能带路径原文，改成 `<redacted-path #N>: denylist`（N 是本次扫描内的文件序号）；路径里含名单词的文件，它的内容命中也用同样的占位代替路径。测试改成断言输出不含原文（现在 scan.test.mjs:103 断言的恰好相反）。README 写明。
5. **成员访问误报（r2 验收没过：最近 6 个 PR 有 39 条）。**
   - 代码类文件（ts、tsx、js、mjs、cjs、swift、kt、kts、java、py、go、rs、sh 等，自己列全写进 README）对**所有** TLD 都要求主机上下文（`://`、`@` 前缀、上下文词）或者整段引号内容就是主机名；md、txt、yml、yaml、json 这类正文仍用完整 TLD 表。
   - 「后面跟 `(` 不算」对所有 TLD 生效。
   - `url.host`、`let host = url.host` 这种右侧是成员访问的，不能因为出现 `host` 就当主机上下文（上下文词后面要直接跟值，不是变量名接 `.`）。 <!-- public-scan: allow domain -->
   - 回归用例至少覆盖：`Date.now`、`Locale.US`、`AES.GCM.open`、`event.target`、`class.java`、`url.host` 在 `.ts`/`.swift`/`.kt` 里不报；同样的文本在 `.md` 里允许报（写明）。 <!-- public-scan: allow domain -->
