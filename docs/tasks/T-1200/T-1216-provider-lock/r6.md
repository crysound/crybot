## 必改
1. remoteOnly 下渲染端的切换环境入口还在，点了没反应：主窗口当前环境是服务器，`workspaceOnly` 放行服务器页面调用 `workspaces:state`，预加载照常暴露 `window.cry.workspaces`，`useWorkspacePlace` 得到 `switchable: true`，侧栏 `src/components/DesktopWorkspaceSwitcher.tsx` 约 68 行、`Sidebar.tsx` 约 1289 行、个人菜单 `SidebarProfileMenu.tsx` 约 583 行的「切换位置」照常显示，而 `electron/main.mjs` 约 2543 行 `workspaces:menu` 直接返回。改成 remoteOnly 时页面拿不到切换入口（例如 preload 不暴露 `workspaces`，或 `workspaces:state` 返回 `switchable:false` 并让前端隐藏，选改动小且关闭开关时行为不变的做法）。补行为测试：remoteOnly 时渲染端看不到切换入口，关闭时仍可见。

## 一并修
2. `electron/main.mjs` 约 1388 行、`electron/menu.mjs` 约 125 行：remoteOnly 下「重新加载 / 强制重新加载」在当前页与服务器同源时分别调用 `webContents.reload()` / `reloadIgnoringCache()`，只有在错误页或其他来源时才导航到服务器首页。补测试。
3. `electron/main.mjs` 约 2899–2901 行 remoteOnly 分支直接用 `desktopBuild.defaultServerUrl` 导航，不依赖 `activeRemote(environmentsState)`；remoteOnly 下启动时 `persistEnvironments` 写盘失败只记日志，内存状态照样更新，不让启动失败。补测试。
4. `electron/remote-only.node-test.mjs` 中「remote-only switching refuses local…」改成显式断言（注入计数桩，断言没有调用切换和持久化）。
