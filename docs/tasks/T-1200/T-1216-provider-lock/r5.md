# T-1216 第 3 轮（改方向）：Boat 直接关掉；桌面端只连服务器

## 背景
本 worktree 已有第 1、2 轮改动（提供方锁定 `CRYBOT_PROVIDER_LOCK=1`、锁定时去掉 Boat、中文「机器人」改「智能体」），说明见同目录 `brief.md`、`r2.md`、`r3.md`，报告见 `report.md`。上一份返工说明 `r4.md` 刚开始执行就被协调者停掉，**作废**：worktree 里如有按 r4 做了一半的改动，只保留本说明第 2、3 条要的，其余退回到第 2 轮结束时的样子（第 1、2 轮改动全部保留）。

用户决定：
- 没有人用过 Boat，锁定时 Boat 直接整个关掉，不需要保留 Boat 的删除、休眠等收尾路径。第 2 轮让 `boatConfigured` 在锁定时为 false 的做法保留。
- 桌面端（Mac/Windows）应该只连部署方的服务器，界面、智能体、对话、提供方都来自服务器，和网页完全一致，不再出现「本机模式」。

## 要做的事
1. **桌面端只连服务器**（新增构建开关，默认关闭，关闭时行为与 main 完全一致）：
   - `desktop-config.json` 增加布尔字段 `remoteOnly`，由构建变量 `CRYBOT_DESKTOP_REMOTE_ONLY=1` 生成（`scripts/desktop-build-config.cjs`），`electron/desktop-build-config.mjs` 读取，要求同时配了 `defaultServerUrl` 才生效。`.github/workflows/release.yml` 顶部 env 加 `CRYBOT_DESKTOP_REMOTE_ONLY: ${{ vars.CRYBOT_DESKTOP_REMOTE_ONLY }}`（只加这一行，协调者会建仓库变量）。
   - `remoteOnly` 生效时：每次启动都确保存在指向 `defaultServerUrl` 的远程环境并设为当前环境——**包括已经有 `environments.json` 的老用户**（现在 `defaultServerEnvironment()` 在已有保存文件时直接返回，老用户会停在本机模式）。
   - 远程页面加载失败（断网、登录未完成等）时，不切回本机、不把本机写进 `environments.json`；窗口显示一个中文的「连不上服务器，重试」页面（可复用现有错误页机制），重试仍加载服务器。
   - 菜单里切换环境 / 本机模式 / 添加其他服务器的入口在 `remoteOnly` 时隐藏；保留「重新加载」之类的必要项。菜单里本来是英文的 Server 等字样，中文系统下显示中文（按现有菜单本地化方式，没有就新增最小实现）。
   - 本机后台服务：如果桌面端其他功能（如本机虚拟电脑、更新、IPC）依赖它，可以照常在后台启动，但窗口永远不显示本机界面；如果确认无依赖，`remoteOnly` 时不启动。二选一，报告里写明选择和理由。
   - 登录跳转：`loginNavigationAllowed()` 依赖当前远程环境，`remoteOnly` 下当前环境始终是服务器，确认 `loginHosts` 里的登录主机在窗口内打开、登录完成后回到服务器页面。补测试。
2. **安全**：锁定且没有端点时放行的首个 `POST /api/instances/claude-endpoint`，显式要求 `ownerOrAdmin(auth)`；补一条 member 得到 403 的测试。
3. **残余文案**：锁定时界面不出现「云端桌面」字样：`keys.section.computers.purpose`（`src/components/keys/key-catalog.ts` 约 15 行）和 `src/lib/bot-overview-text.ts` 约 46 行，锁定时换用不提云端桌面的文案（新增文案中英文都补，其他语言按 i18n:check 要求处理）。
