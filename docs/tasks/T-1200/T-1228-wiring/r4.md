## 必改 1：单屏下挂起轮次的恢复判断要回到 main
- 位置：`server/index.ts:3729` 和 `:3877`。
- 现状：判断改成了 `!(localVmScreensHost.free(seat) ?? (!sharedVm.personHolds(seat) && turnResources.free(seat)))`。screens=1 时 `free()` 对 `computer:vm:shared` 返回 undefined，于是走到 `personHolds`，读的是 `desktop:local/shared` 的接管状态。结果是单屏下只要有人接管着共享 VM，挂起的轮次就一直不恢复。main 的做法是资源一空就恢复轮次。
- 改法：接管判断只用于屏资源，两处一起改，例如 `!(localVmScreensHost.free(seat) ?? ((!isScreenResource(seat) || !sharedVm.personHolds(seat)) && turnResources.free(seat)))`。函数名以代码里实际的为准，没有就写一个小判断函数。
- 补测试：一条单屏用例（有人接管共享 VM 时，资源空出后挂起轮次照 main 行为恢复），一条多屏用例（屏被接管时不恢复）。

## 必改 2：单屏下切换 shared↔per-bot 回到 main 的检查
- 位置：`server/routes/config.ts:366`、`:547-549`、`:610-613`；`server/index.ts:12356-12357`。
- 现状：`changingLocalVmMode` 把「纯模式切换」和「1↔多屏切换」合在了一起。screens=1 下切换 shared↔per-bot 时，也会走 `localVmTurnsBusy`：任何处在 setup 阶段的直接会话都会让它返回 409，即使那个会话跟 VM 无关。同时还会调用 `localVmScreensChanged(true)`，触发 reset、observe 和后台 sweep。
- 改法：`localVmTurnsBusy` 和 `layoutChanged`、`localVmScreensChanged` 只在 `changingScreenLayout`（屏数或布局真的变化）时生效。纯模式切换完全走 main 原来的检查：`localVmActiveThreads`、lifecycle、image。
- 补测试：在 routes/config-screens.test 里加一条，screens=1 下纯模式切换时，有一个与 VM 无关的 setup 会话也不返回 409，且不触发 screens 变更回调。
