## 必改
1. **启动竞态**（`server/index.ts` 约 6224 行）：`recoverLocalVms` 排在 `localVmScreensHost.recover()` 之后，后者要做多次 exec，`localVmSeen` 很晚才填上；服务刚起来的回合 `attachLocalVm(false)` 看到 `localVmSeen.has("shared")` 为 false 直接返回，拿不到 computer MCP。e2e 场景 2（20s 超时）、3（409 "This conversation does not show that desktop"）、5（找不到 `stop screen-s2:*`）都是这个原因（审核员在 fixture 起来后加等待即全过）。改法：引入启动恢复完成的 ready promise，attach/claim 前等它；`recover`、`recoverLocalVms`、`sweep` 拆开各自 catch 并记日志（不要一个抛错就静默跳过后面的）。e2e fixture 等 ready（例如轮询一个已有的状态接口或日志标记），不要固定 sleep。
2. **多屏模式不得提前占屏**（`index.ts` 约 8059、8114 行 `claimAutoLocalVm`，7954 行）：多屏模式下 `lazyReadyVm` 一直为 null，Auto 回合在 setup 就 claim 一块屏，纯聊天也占屏，4 块占满后第 5 个机器人纯文本也要排队直至 park。改为和 main 一致的懒占用：第一次调用屏幕工具时才 `localVmScreensHost.claim`；只有 strict 回合提前占用。多屏模式下 `claimAutoLocalVm` 也要尊重 pinnedTarget。补测试：Auto 回合纯文本不占屏；4 屏全忙时纯文本回合不排队。
3. **前后端共用类型 + D 联调**：`src/components/LocalVmScreens.tsx:16` 自定义的 `ScreenListPayload` 删掉，前端（含 `LocalComputerSection.tsx`）改为 import `shared/local-vm-screens.ts`；字段对不上就以服务端实际返回为准调整 shared 类型并让前端适配。report 里「D 未合入」改正。联调证据：写一个可重复运行的组件/接口契约测试（用服务端路由真实输出喂前端组件或断言字段），截图由协调者在真实环境出。
4. **截图请求不算活动**（`server/routes/computers.ts:298-306`，305 行 `deps.screens.touch(target)`）：设置页每 5 秒轮询截图，会让屏永不空闲。admin 截图、join 路由不 touch；只有回合内工具调用和 `touchControl`（人工控制）续期。bot 截图路由（约 459 行）按同一口径检查。补测试：连续截图不阻止空闲回收。
