2. **单屏接管被悄悄交还**（`ComputerPanel.tsx:661`）：接管会话键拼进了 `liveTarget`，主状态 effect 每次重跑都先清空 `resolvedComputerSelection`，`liveTarget` 短暂为 null，会话键变化，`useComputerTakeover` 调 `leave()` 发 release。screens=1 和独占模式下，人接管期间只要 section、vps 别名、能力就绪、driverKind 等依赖变化，控制就被交还。改为：会话键只在拿到明确屏目标时才包含它（例如用 ref 记住最近一次非空的 `vmStatus.screen?.viewerTarget`），不要用会短暂变 null 的值；无屏目标时会话键与改动前完全一致。补测试：单屏（per-bot）接管期间触发状态重新拉取，不产生 release、画面不关闭。
3. **服务端未返回 screens 时不显示屏数设置**（`LocalComputerSection.tsx:1323-1326`）：现在服务端不返回 `status.screens`，`parseConfigPatch({ localVm: { screens: 2 } })` 会丢掉该字段；第一批合并后设置页会显示「屏数 4、8G/3 核」，用户改了提示成功却什么都没变。改为：只有 `status.screens` 存在时才渲染屏数设置和资源说明，不要用 `?? 4` 兜底。补测试：没有 `screens` 字段时不显示。
