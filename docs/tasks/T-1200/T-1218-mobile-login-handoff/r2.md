# T-1218 第 2 轮返工：回跳里不能出现明文令牌

原任务说明：`docs/tasks/T-1200/T-1218-mobile-login-handoff/brief.md`（仓库相对路径，先完整读一遍，目标、范围、验收标准不变）。第 1 轮改动已提交在本分支，摘要见同目录 `report.md`，在此基础上继续改。

## 本轮必须修的

### 1. 安全审查「高」：完整 Access JWT 明文放在 `crybot://auth?...&token=` 里
自定义 scheme 不独占，设备上别的 App 注册同一 scheme 就能拿到令牌冒用身份。state 不是秘密，防不住。

改法：**App 端生成一次性密钥对，服务端把令牌加密给这把公钥，回跳只带密文**。不新增任何无需登录的接口（服务器前面整站都有 Access，不能开放新路径）。

协议（v1，两端和服务端严格一致，写进 `docs/self-hosting.md` 的接力说明里）：
- App 每次登录生成新的 P-256 密钥对，私钥只存内存（安卓冷启动恢复需要时可存 SharedPreferences，用完即删），公钥用 X9.63 未压缩格式（65 字节，0x04 开头），base64url 无填充，作为参数 `pk` 与 `state` 一起发给 `GET /auth/app-handoff?state=...&pk=...`。
- 服务端：`pk` 必须能解析成合法 P-256 点，否则 400。生成服务端临时 P-256 密钥对，ECDH 得共享密钥；`HKDF-SHA256(ikm=共享密钥, salt=state 的 UTF-8 字节, info="crybot-app-handoff-v1", L=32)` 得 AES-256 密钥；随机 12 字节 nonce，AES-256-GCM 加密 JWT，AAD 为 state 的 UTF-8 字节。
- 回跳：`<scheme>://auth?v=1&state=<state>&epk=<服务端临时公钥 X9.63 base64url>&iv=<nonce base64url>&ct=<密文||16字节tag base64url>`。**URL、HTML、日志里都不得出现明文 JWT**。
- iOS：CryptoKit（`P256.KeyAgreement`、`sharedSecret.hkdfDerivedSymmetricKey(using: SHA256.self, salt:, sharedInfo:, outputByteCount: 32)`、`AES.GCM.SealedBox(nonce:ciphertext:tag:)`）。
- 安卓：只用平台 API（`KeyPairGenerator("EC")` + `ECGenParameterSpec("secp256r1")`、`KeyAgreement("ECDH")`、用 `Mac("HmacSHA256")` 手写 HKDF、`Cipher("AES/GCM/NoPadding")`），不加依赖。原始点和 `ECPublicKey` 之间的转换自己写，注意坐标补齐到 32 字节。
- 解密失败、版本不是 1、参数缺失：当作登录失败，显示错误面板和「登录」重试按钮。

### 2. 安全审查「低」：安卓 `onNewIntent` 里 `setIntent(intent)` 后 Activity 一直持有回调 URL
回调处理完后清掉（例如 `setIntent(Intent())`），冷启动 `onCreate` 收到回调后同样清掉。
