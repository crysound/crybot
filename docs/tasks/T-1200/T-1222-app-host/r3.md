## 必改
1. **`server/app-host.e2e.test.ts` 的 Host 根本没生效。** Node 24 的 `fetch` 会忽略调用方设的 `Host` 头，服务端收到的是 `127.0.0.1:<port>`，所以两组 Host（app.example.com / legacy.example.com）实际都没测到。
   - a) `request()` 改用 `node:http` 的 `request({ host: "127.0.0.1", port, path, method, headers: { host, ... } })`。WebSocket 用例已经用原始 socket，不用动。加一条自检断言：服务端看到的 Host 确实是传入的值（例如对一个只在 App 主机返回 200 的路径，在 legacy 主机上必须 404）。
   - b) 换成真实 Host 后，`/` 和 `/pair` 会返回 403（`server/request-auth.ts:710`，非 loopback Host），原因是夹具没有静态目录。夹具加 `CRYBOT_STATIC_DIR` 指向临时目录，放一个 `index.html`，两组都应 200。
   - c) 有了静态目录后，GET `/auth/feishu/start`、`/auth/feishu/callback` 会走 SPA 回退返回 200（飞书路由属任务 01，main 上还没有）。期望按现状写并加注释说明原因，不要写成 `[400,404]`。邮箱 start/verify 是 POST 路由：清单里按 **POST** 断言没开邮箱登录时 404（规格 3.5）。
   - d) 限流段：限流键是来源 IP，前面清单已经用掉配额；`/api/pair` 错误配对码还会先触发 `server/sessions.ts:47` 的 `PAIRING_LOCKOUT`。改成用一个没用过的来源（App Host 加 `X-Forwarded-For: 203.0.113.77`），对 POST `/api/auth/email/start` 打 11 次：前 10 次断言响应体不是 `rate_limited`，第 11 次断言 429、响应体 `{"error":"rate_limited"}`、带 `Retry-After`。不要断言「状态码不是 429」。
2. **端到端补齐 r2 必改 2、3 要求的用例。**
   - 照 `scripts/smoke-selfhost-login.mjs:23-46` 的做法：起本地 JWKS 服务，用 `--import` 预加载把 `https://<team>/cdn-cgi/access/certs` 改指到本地，配 `CRYBOT_CF_ACCESS_*`，用测试密钥签 JWT（团队名用 `example.cloudflareaccess.com` 这类虚构值）。
   - 用例：主域名 + 有效 JWT → `/auth/app-handoff` 不是 404；主域名 + 有效 JWT + 配对得到的 cookie 会话 → 不是 404；无效 JWT → 401。
   - 「什么都没配」组（约 96-104 行）复用同一份完整清单，用真实 Host 断言行为和 main 一致；清单补上 `cloudSigned` / `chatApps.serveFile` 路径和上传（POST）。
3. **`server/index.ts` 不许把多条语句挤进已有行。** 现在 12610、12617、12686、12689、12712、12715、12815、12907 行都在旧行尾接了 `...; if (...) return;`，12715 还把原来独立一行的注释 `// The shape the companion apps decode...` 挪到了新语句后面。
   - 两个 `appGate` 调用：合进已有判断（例如 `if (await desktopUpdateFiles(...) || appGate(...)) return;`）或各占一行。
   - 6 处 `authAudit` 收进 app-host：例如 `appGate` 对配对、登出路径挂 `res.once("finish")`，按路径和状态码写审计；或导出一个 `auditPair(req, result)`，index 里只调一次。
   - 恢复那行注释的原位置和原文。
   - `index.ts` 行数不得超过 15460（分支起点），也不得用挤行的方式达标。
4. **`server/auth-rate-limit.test.ts:24-33` 淘汰测试是空转的。** 改成：用 `maxKeys` 很小的实例，先让 key0 打满（确认被限），再插入超过上限的其他键，断言 key0 被淘汰后重新放行，并断言内部键数不超过上限。验证：临时删掉淘汰逻辑，这条必须变红（报告贴红灯输出，再改回）。

## 本轮一起做的建议（协调者已定）
5. **App 回跳 origin：** 没配 `CRYBOT_APP_LINK_ORIGIN` 但配了 `CRYBOT_APP_HOST` 时，用 `https://<CRYBOT_APP_HOST>` 作为 origin（兜底页、app-handoff 回跳都用它）；两者都配且主机不一致时启动告警一次（不含密钥）。弃用警告文案相应改准。加单测覆盖三种组合。
6. **`server/app-links.test.ts:102-112`：** 危险参数用例从 `href` 和 `location.replace(...)` 里取出目标，与 `` `crybot://auth?${query}` `` 全等比较，查询串里带 `epk`、`iv`、`ct`，断言 `<script` 只出现 1 次；去掉空断言 `not.toContain("<script>alert")`。飞书用例同样改成全等比较。改正和实际不符的测试名。
7. **审计补全：** 邮箱 verify 登录写审计（本轮允许最小改动 `server/routes/email-sign-in.ts`，只加审计调用）；`DELETE /api/auth/sessions/:id` 审计带上身份标签（`auth.session.label`）。审计内容不含验证码、令牌、Secret。
8. **`appGate` 单测：** 用 `memoryHttp` 补一条 429 响应体 `{"error":"rate_limited"}` 和 `Retry-After` 数值的单测。
9. **报告**按实际情况写：哪些 e2e 在沙箱里跑不了，交给协调者补跑；不要写「逐条覆盖」而仓库里没有对应用例。
