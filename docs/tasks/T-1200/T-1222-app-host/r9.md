# T-1222 app-host 第 9 轮：app-host e2e 路由表与 main 的飞书路由不一致

仓库 crybot，分支 T-1222-app-host（复用 worktree，已提交并合入 main，head 5401d181）。第 3 轮以后：只修必改。

## 现象
Actions run 43611325640，`server/app-host.e2e.test.ts` 两个用例失败：
- runs the unauthenticated surface against a real server for app and legacy proxy hosts
- keeps an unconfigured instance's complete public surface unchanged
都是 `app.example.com GET /auth/feishu/start: expected 404 to be 200`（第 146 行断言，158、191 行调用）。

## 分析方向
main 合入了飞书直登（feishuExchangeRoute / FEISHU_CONFIG 等）：飞书未配置时 `/auth/feishu/start` 返回 404。本分支 e2e 的路由表仍按旧行为期望 200。

## 要做
1. 先核实 main 上 `/auth/feishu/start` 在「飞书未配置」和「已配置」两种情况下、在 app 主机和旧代理主机上的应有状态码（看 server/feishu-routes*.ts 和 index.ts 的接线）。
2. 按真实设计更新 e2e 路由表：未配置时期望 404；如测试里有「已配置」的分支，补上对应期望（例如 302 跳转）。不得为了过测试改产品代码；如果发现是本分支合并顺序导致的产品缺陷（例如已配置时在 app 主机上被门挡掉），停下并在报告里给证据。
3. 同文件里其他飞书相关路由（/auth/feishu/*、/api/auth/feishu/exchange）一并核对。
