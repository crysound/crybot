# T-1222-app-host 第 8 轮：解决与 main 的合并冲突（server/index.ts）

## 背景
本分支（各端飞书直登回跳，PR #29）已审过、安全审查通过。main 先合入了 T-1222-feishu-core（#30），协调者已在本 worktree 执行 `git merge origin/main`，`server/index.ts` 约 12540 行出现一处冲突，其余文件已自动合并。两边都改了请求入口的前置路由：
- 本分支（HEAD）：`desktopUpdateFiles || appGate(req,res,path,false,true) || appLinks` → `cfAccessRefusal` → `appGate(..., accessVerified(req))` → `appHandoff(req,res,url)`。
- main：`desktopUpdateFiles` → `appLinks` → `appHandoffGate(req,res,url,method,path,sessions,SESSION_COOKIE,json)` → `feishuExchangeRoute({...})`。

## 要做的
1. 解决冲突，保留两边的功能：本分支的 appGate / Cloudflare Access 判定 / app handoff，和 main 的 appHandoffGate、feishuExchangeRoute 都要在。先弄清 `appHandoff` 与 `appHandoffGate` 是否是同一件事的两版实现（看两边的 server/app-handoff.ts 及其 git log）：是同一件事就合成一份，不要留两条重复的 `/auth/app-handoff` 处理；不是就按依赖顺序都保留。
2. 顺序要保证安全语义不变：需要登录/Access 校验的路由不能被挪到校验之前；飞书交换接口按 main 的位置和条件（它自己做校验）。在报告里写清最终顺序和理由。
3. 检查自动合并的其他文件里有没有重复定义、重复 import、两版 app-handoff 测试互相矛盾，一并处理。
