# T-1221-app-shell 第 5 轮（iOS 测试崩溃：协作线程栈溢出）

## 上一轮情况
Actions「Mobile builds」iOS 测试执行失败（main 上通过，分支独有）。7 个用例崩溃后被 XCTest 重启：
- AppStoreTests：testLateSnapshotCannotRestoreSignedOutState、testReplayMessageUpdatesLiveState、testTeamPicturePathUsesTransportAndPreservesVersionQuery
- ConnectionTests：testAttachLoadsSnapshotAndDetachStopsStream、testLiveInboxBadgeRefreshesAfterSnapshotAndRelevantFrames、testPauseDuringSnapshotRequiresAnotherSnapshotOnResume、testSlowInboxRefreshDoesNotBlockFramesAndCoalescesChanges

协调者解出的 7 份崩溃报告完全一致：
```
EXC_BAD_ACCESS / SIGBUS  KERN_PROTECTION_FAILURE
message: Could not determine thread index for stack guard region   ← 栈溢出撞到保护页
thread queue: com.apple.root.user-initiated-qos.cooperative          ← Swift 并发协作线程（栈很小）
  outlined init with copy of WireMessageFields
  WireMessage.encode(to:)  WireModels.swift:2770
  ... JSONEncoder / Array<A>.encode(to:) ...
  JSONValue.init<A>(encoding:)  JSONValue.swift:58
  （上层来自测试替身 ShellControlledTransport.send / ShellDelayedTransport.send）
```
原因：`WireMessageFields`（WireModels.swift:159 起，字段非常多）是很大的值类型；`WireMessage` 是普通 enum，每个 case 直接内嵌一份 WireMessageFields。Debug 构建下 `encode(to:)` 的 switch 为每个 case 的 `let value` 各开一块栈空间并整份拷贝，再经 `JSONValue(encoding:)` 递归进 JSONEncoder，编码消息数组时在协作线程（栈远小于主线程）上溢出。本分支新加的测试替身在 async 上下文编码消息数组，所以只在本分支触发；真实 App 在后台任务里编码/解码消息时同样会崩，属于生产缺陷，不是测试问题。

## 必改
1. **让消息模型不再在栈上整份搬运大结构体**，从根上修，不要靠改测试或换线程绕开：
   - `WireMessage`（以及同样以 case 内嵌 `WireMessageFields` 或其他大结构体的 enum，请全文件排查，包括 SSE 帧 enum）改为 `indirect enum`，或给 `WireMessageFields` 加写时复制的堆存储（`final class` 盒子 + 计算属性，保持对外 API、`Hashable`/`Equatable`/`Sendable`/`Codable` 行为和 JSON 形状完全不变）。二选一，优先 `indirect enum`（改动小）；如果 indirect 后 Debug 下 encode 的 switch 仍会把 payload 拷到栈上，就用堆存储方案。
   - `encode(to:)` / `init(from:)` 里不要为每个 case 先拷出整份值再转 `JSONValue`：能直接 `try value.encode(to: encoder)`（或单值容器）就直接编码，避免 `JSONValue(encoding:)` 这一层再起一个 JSONEncoder 递归。前提是输出 JSON 与现在逐字节语义一致（kind 字段、未知 kind 原样往返），已有契约样本测试必须原样通过。
2. **补回归测试**（放进 CryKit 的测试，Linux `swift test` 也能跑）：在 `Task.detached` 里（协作线程）编码再解码一个含 500 条各种 kind 消息的数组和一个含这些消息的快照/线程页，断言往返相等。Debug 构建下修复前应会崩。
3. 上面 7 个用例本身的断言不改。如果测试替身里有不必要的大值拷贝也可以顺手收紧，但不得以此代替第 1 条。
