# T-1242 第 7 轮：readFile 加大小上限（配合任务 ② 的安全审查中级问题）

原任务见本文件夹 brief.md、r2.md–r6.md，工作区里上一轮改动保留。只做下面一条。

## 必改
任务 ②（智能体操作电脑工具）的安全审查指出：machines.readFile 会把整个文件读进内存，大小检查在读完之后，智能体可把文件换成几 GB 拖垮共享服务进程。本任务提供 readFile 的真实实现，所以在这里堵：
1. server/instabox/machine.ts 第 20 行接口**一字不差**改为：
   `readFile(machineId: string, path: string, options?: { maxBytes?: number }): Promise<Uint8Array>;`
   （任务 ② 同步改了同一行，两边必须完全相同，避免合并冲突。）
2. server/instabox/machines.ts 的 readFile 实现（及其调用的 client 层）：maxBytes 缺省 256 MiB；先看响应 Content-Length，超过直接拒绝并取消响应体；再按流式读取累计字节，超限立刻中止读取（取消 reader / abort），不得先缓冲完整内容再判断。错误要清楚（含 maxBytes 数值，不含钥匙、地址）。
3. 补测试（用本仓库假 服务）：Content-Length 超限被拒；无 Content-Length 的分块响应超限时中途中止，且测试能证明没有读完全部内容（例如假服务记录被取消/只发出部分块）；正常大小文件读取不变。
