# T-1252 第 11 轮：删除时，记录在案的 机器没核实清理前，不清记录、不删智能体

原任务见本文件夹 brief.md 和 r2–r10.md。工作区已有改动全部保留，包括第 9 轮修好的 19 个 CI 失败和第 10 轮的持久记录 machine-records。产品规则不变。这是第 3 轮以后的返工：只修下面这一个必改项，不扩大范围。

## 必改（第 7 轮审核）
server/instabox/machines.ts 的 remove（约 103–109 行）。现在的流程是 find(botId) 按名字查，查不到就直接 `records.forget(botId)`，删除随即成功返回。

问题场景：建过机器的智能体，后来密钥被换成另一个 账号的有效密钥。比如环境密钥去掉后，回退到另一账号的配置密钥。新账号下查不到原机器，结果本地记录和智能体都删了，原机器还在原账号里继续计费，DELETE 一次都没调用。

## 改法（按这个设计做）
1. machine-records 每条记录除了 botId → machineId，再存一个当前密钥的指纹。
   - 指纹用 sha256 的前 16 位十六进制，绝不存明文密钥。
   - remember 时把指纹一起写入。
   - 这个文件只在本分支引入、尚未上线，不需要兼容旧格式。但读到旧的两元组时不要崩溃，按「指纹未知」处理。
2. remove 的规则：
   - 先 find：找到了就照原来的方式 DELETE，成功后 forget。
   - find 没找到，并且没有记录：直接成功，等于从未建过机器。
   - find 没找到，但有记录：用记录里的机器 ID 调 GET 单台机器接口核实。
     - 当前密钥指纹和记录一致，并且返回 404 或状态为 deleted：才 forget 并成功。
     - 指纹不一致、指纹未知，或者核实失败、返回其他状态：保留记录，抛错，返回 503。错误信息写明：这个智能体的云电脑是用另一把 密钥创建的（或无法确认已删除），请恢复原密钥后再删除。
   - deleteBotWithLifecycle 收到这个错误时保留智能体，沿用第 10 轮已有的 503 路径。
3. 回归测试，用隔离的假请求：
   - 记录在 A 账号，当前密钥是 B 账号，list 返回空 → 删除返回 503，记录还在，智能体还在，DELETE 调用 0 次。
   - 同一把密钥，list 返回空、GET 单台返回 404 → 删除成功，记录清掉。
   - 第 10 轮已有的「建机 → 去掉密钥 → 重启 → 删除返回 503」「从未建机删除成功」两个测试继续通过。
4. report.md 顺带修正：第 10、11 轮的「当前改动」清单按 `git diff HEAD --stat` 加未跟踪文件如实列出，verification.txt 末尾的文件数同步改对。
