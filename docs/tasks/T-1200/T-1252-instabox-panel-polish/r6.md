# T-1252 第 6 轮：线上开了 provider lock 后，界面把云电脑整个锁成了 VPS

原任务见本文件夹 brief.md、r2–r5.md，工作区里已有的改动全部保留。这一轮只修下面这一项，不做别的改动。

## 背景
线上设置了 `CRYBOT_PROVIDER_LOCK=1`，这个开关原本只是用来关掉 Boat（另外把模型引擎限制在 claudeAgent，这部分照旧不动）。但前端把 `state.config.providerLock` 当成了「云电脑只能用自托管 VPS」来处理，于是线上用户：
- 看不到「云端桌面」，只看到「自托管 VPS」；
- 看不到 选项；
- 选云电脑时被强制写成 `cloudBackend: "vps"`。

涉及的位置（行号是大约位置）：
- `src/components/bot-settings/AccessSection.tsx`：604 行，开了 lock 时整个后端选择器被隐藏；640、658 行，强制写 vps。
- `src/components/ComputerPanel.tsx`：121、148、355、377、1104、1118、1119、1124、1143、1147、1508、1656 行，开了 lock 时一律当作 vps 处理，显示的文案也是「自托管 VPS」。
- 服务端 `server/index.ts`：约 1929 行的 `boatNotConfigured`，约 6011 行的 `surfaces` 过滤。这里只拦 `box`，是对的。

## 必改
1. **前端的 providerLock 只等于「Boat 不可用」。** 开了 lock 时，云电脑照常可选，显示名称仍然是「云端桌面」，后端选择器照常显示「自托管 VPS」和「」两项，默认 。也就是说，开了 lock 和没开 lock 的界面和行为完全一样，因为第 2–5 轮已经把 Boat 从界面上去掉了。所有「lock 就强制 vps」的分支都改成「lock 时把 box 当成不可用」，有效后端的推导和第 4、5 轮定下的默认规则保持一致。
2. **以前被强制存成 `vps` 的智能体保持 vps 不动。** 不做自动迁移，用户可以自己切到 。
3. **服务端也要核对。** 开了 lock 时，的开机、画面、快照、工具、预览选择都要正常可用，不能被 lock 拦掉。lock 只拦 box。只修服务端里确实把 拦掉的地方，模型引擎的 lock 逻辑不碰。
4. **补测试。** 开了 providerLock 时：设置页能看到 VPS 和 两项，默认 ；选择云电脑后写入 `instabox`；ComputerPanel 显示「云端桌面」而不是「自托管 VPS」；服务端开了 lock 后 的开机路径可用。已有的 providerLock 测试按新行为同步更新，除此之外的覆盖保留。
