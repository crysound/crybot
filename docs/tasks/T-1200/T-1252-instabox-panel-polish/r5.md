## 必改
1. **默认 不能影响 Auto 模式下的本地桌面预览。** `server/index.ts` 约 5988 行遇到 就直接返回 `"cloud"`。默认值改了以后，以下智能体在 Auto 模式、会话还没固定工作位置时，即使共用 Local VM 已经就绪，也会跳过后面的 VM 和本机检查（没有 密钥时也一样），结果是本地桌面的预览和唤醒入口没了：
   - 新建的智能体；
   - 没保存过后端的旧智能体。

   改法：Auto 模式下的预览选择保留原来对本地桌面的检测顺序和选择规则。只有满足下面任一条件时才选 云电脑：
   - 智能体明确选了 ；
   - 它的 机器已经存在且可用。

   请自行判断最小改法，但要守住一条：共用 Local VM 和多屏的行为跟 main 完全一致。

   补隔离回归测试：后端用默认值、没有 密钥、共用 VM 已就绪时，Auto 仍然选本地桌面。

2. **没写明后端、实际在用 的智能体，切走时也要让机器休眠。** `server/instabox/power.ts` 约 86 行的 `withInstaboxBackendPower()` 现在只处理显式写了 `"instabox"` 的情况。没保存 `cloudBackend` 的智能体经 `/computer/provision` 起了 机器后，再 PATCH 切到 VPS，会绕过休眠，机器一直开着。

   改法：切换前和切换后都按有效后端判断，用的是和 `server/cloud-backend.ts` 同一套默认规则。

   补测试：后端字段缺省 → 启动 → 切到 VPS，断言调用了 suspend。
