# T-1232-feishu-broker 第 7 轮（只改测试：开盒端到端场景）

原任务说明 `docs/tasks/T-1200/T-1232-feishu-broker/brief.md` 及同目录 `r2.md`–`r6.md`，先读。第 5、6 轮改动已提交在分支上。本轮**只改 `server/feishu-cli/server.e2e.test.ts`**，生产代码不动。

## 上一轮情况
在有 bwrap 的主机上实跑，sandbox=true 场景报 `provider instance "" is unavailable`（约 106 行）。协调者排查出三个叠在一起的测试侧问题（生产代码行为正确）：
1. **PATH 顺序**：测试把 bwrap 所在目录（如 `/usr/bin`）放在 PATH 最前，假 CLI 的 `#!/usr/bin/env node` 于是用到系统里较旧的 node，加载 `.ts` 报 `ERR_UNKNOWN_FILE_EXTENSION`；版本探测失败，claude 实例 unavailable，机器人 instanceId 为空。
2. **套接字放在代码根下**：`process.cwd()/.tmp-feishu-host-*/broker.sock` 位于代码根，盒内只读可见，`config.ts` 的路径校验按设计停用代领（日志「飞书代领套接字路径对非授权盒子可见，已停用」），授权轮次拿不到令牌。
3. **TMPDIR 在数据目录里**：测试服务的 TMPDIR 被 `scripts/control-cry.ts` 设为 `<dataDir>/tmp`，驱动把 `--append-system-prompt-file` 写到 tmpdir 下；盒子规划不把数据目录内未列入 ro 的路径挂进盒内，CLI 报 ENOENT 退出。线上 TMPDIR 是 /tmp，属测试夹具问题。

协调者在副本里按下面改法实测：`Tests 2 passed (2)`，两个场景都实跑。

## 必改（只改 server.e2e.test.ts）
1. 服务 PATH 把 node 所在目录放最前：`[dirname(process.execPath), bwrap 目录, process.env.PATH]`（过滤空值，用 `delimiter` 连接）。
2. 套接字改放 `mkdtemp(join(tmpdir(), "feishu-broker-"))` 新建的目录下（`/tmp` 下的独立目录，盒内是私有 tmpfs，非授权盒子看不到）；假 CLI 目录仍放代码根下。
3. 仅开盒场景给服务传 `TMPDIR`/`TMP`/`TEMP` = 上面那个目录下的 `tmp` 子目录（先 mkdir）；sandbox=false 场景的环境保持原样。
4. 代码根改用 `fileURLToPath(new URL("../..", import.meta.url))` 求得，不依赖 `process.cwd()`。
5. finally 里删除套接字目录；令牌泄漏扫描把该目录下的 `tmp` 子目录也纳入。
