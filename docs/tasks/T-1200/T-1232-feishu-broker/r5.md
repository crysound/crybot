## 必改
1. **沙箱关闭时不得启用代领（中危）**。`box: off` 时所有智能体都以同一个系统用户运行，任何智能体（名单外用户的轮次、群聊、例行任务、被提示注入的智能体）都能直接连 `token.sock` 拿令牌，也能读同用户其他进程的 `/proc/<pid>/environ`。同一系统用户下代码层面补不上，所以改为失败关闭：
   - `feishuCliAccess`（或等价的启用判断）在沙箱检测结果不是 `bwrap` 时，一律不注入、不挂套接字，启动时打一条固定文字告警（例如「飞书代领需要开启智能体沙箱，当前未开启，已停用」），不含路径和身份。
   - 沙箱开启时，套接字只挂进名单用户发起的轮次的盒子（现有 `box.rw` 逻辑），确认别的轮次的盒子里看不到这个路径；补测试。 <!-- public-scan: allow domain -->
   - report 和安装说明把「必须开启沙箱（`CRYBOT_BOT_BOX=on`）」写成上线前置条件，不再只列为已知局限。
2. **名单只允许一个人（低 1）**：一个 broker 只对应一份员工凭证。`CRYBOT_FEISHU_CLI_USERS` 解析后超过 1 项就失败关闭并告警（固定文字），等以后有按人路由的多 broker 再放开；补测试。
3. **飞书轮次进行中拒绝非发起人的追加消息进入同一进程（低 2）**：读 `server/drivers/claude.ts` 的 steer 路径。带令牌的飞书轮次进行中，如果追加消息的发起人不是本轮发起人，不能 steer 进这个进程，改为排队到本轮结束后（按现有排队行为）或按现有拒绝方式处理；补测试。改 claude.ts 时注意 `scripts/testing/file-size-ratchet.test.ts`：claude.ts 不能超过 2087 行，新逻辑放到 `claude-turn-launch.ts` 或 feishu-cli 下的模块。
