# T-1232-feishu-broker 第 6 轮（小修：沙箱端到端测试）

## 上一轮情况
r5 的必改 1–5 生产代码和文档都已落实，复审确认。只剩新增的 `server/feishu-cli/server.e2e.test.ts` 沙箱场景（sandbox=true，约 213-224 行）有问题：在能跑 bwrap 的 Linux 主机上必然失败，在没 bwrap 的 CI 上被跳过，等于从没验证过。复审在有 bwrap 的主机上查到两个原因：
1. 跳过条件 `canBox` 用测试进程的 PATH 找 bwrap，但被拉起的服务进程 PATH 被 `scripts/control-cry.ts` 的 `verificationServerEnvironment` 固定成 `dirname(process.execPath)`，服务日志 `bot box: off (no-bwrap)`，按设计失败关闭，拿不到令牌（第 92 行 `expected undefined to be 'fixture-host-short-token'`）。
2. 把 bwrap 目录加进服务 PATH 后盒子开启了，但假 CLI 放在 `tmpdir()` 下，盒内 /tmp 是私有 tmpfs，看不到，轮次报 `claude exited 127 before result`。

## 必改
1. **让 sandbox=true 场景真正跑通**：
   - sandbox=true 时把 bwrap 所在目录并入传给服务进程的 PATH（只在这个测试里，经测试自己的环境参数传入；不要改 `verificationServerEnvironment` 对其他测试的默认行为，确需改就加可选参数）。
   - 假 CLI 和它的转储目录放到盒内可见的位置（智能体工作目录或代码根下的测试临时目录，测试结束清理），不要放 `tmpdir()`。
   - `canBox` 改为与服务相同的判断：用 `server/bot-box/detect.ts` 的 `detectBox`（传入将给服务的同一份 env）判断能否开盒，不能就跳过并打印跳过原因。
   - 断言：授权用户的轮次拿到短期令牌、盒内能连上套接字；名单外用户的轮次在盒内看不到套接字路径、拿不到令牌。
   - 本沙箱跑不了 bwrap 就写明「未在沙箱运行」，协调者会在有 bwrap 的主机上实跑。
2. **report.md 第 5 轮里「后者仅在宿主可运行 bwrap 时执行」的说法改正**，第 6 轮一节写清现在的跳过条件和覆盖范围。
