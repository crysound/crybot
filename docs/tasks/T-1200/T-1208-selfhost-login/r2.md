# T-1208 第 2 轮(复审和安全审查的建议，只改下面几条)

原任务见同目录 brief.md，执行规格见 `docs/specs/2026-11-13-crybot.md` 第 6、7 节。第 1 轮复审通过，安全审查通过(无高中危)。下面几条改进一并做，其余不要动。

1. **Access 会话按身份复用**(`server/cf-access.ts`)：现在每个带有效 JWT、但不带 cookie 的请求都会新签一个 owner 会话，curl 或 Access 服务令牌这类客户端会让 sessions.json 无限增长。改法：
   - 会话记录里存 Access 身份(JWT 的 `sub`，没有就用 email)。
   - 同一身份已有未过期的 Access 会话时，复用它并回写同一个 cookie，不新建。
   - 为 Access 签发的会话设上限(例如每个身份最多 5 个)，超出时淘汰最旧的。
   - 请求带有效 JWT 和有效 cookie，但 cookie 对应会话记录的 Access 身份与 JWT 的 `sub` 不一致时，作废这个 cookie 会话，再按 JWT 的身份重新签发或复用。
   - 补单测：同一 sub 连续 5 个无 cookie 请求只产生 1 个会话；sub 不一致时旧会话作废。
2. **服务器主机的弹窗仍交给系统浏览器**(`electron/main.mjs` 的 `setWindowOpenHandler`，约 2016 行)：只有 `CRYBOT_LOGIN_HOSTS` 里的主机允许在窗口内打开，服务器主机的 window.open 或 target=_blank 链接恢复为外部打开，保持改动前的行为。顶层导航的规则不变。被拦截导航自动打开系统浏览器的情况，同一 URL 在 2 秒内只打开一次(简单去抖)。补 node-test。
3. **更新源和默认服务器只接受 https**：`scripts/desktop-build-config.cjs` 和 `electron/desktop-build-config.mjs` 里，`CRYBOT_UPDATE_FEED_URL` 和 `CRYBOT_DEFAULT_SERVER_URL` 只接受 `https:`，`http:` 只对 localhost、127.0.0.1、[::1] 放行，其他情况构建时报错。补测试。
4. `scripts/ci-scope.mjs` 第 222、268 行附近：正则补上 `electron-builder.base.yml`、`electron-builder.config.cjs` 和 `scripts/desktop-build-config.cjs`，让只改这些文件的 PR 也触发 Windows 任务。`scripts/mac-thin.mjs`、`scripts/prepare-duckdb.mjs`、`build/dmg/README.md` 注释里的旧文件名改成新的。
