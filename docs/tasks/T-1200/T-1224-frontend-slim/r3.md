## 必改

1. **语言包全部加载失败时白屏**（`src/lib/i18n.ts` 约 31–41 行、`src/main.tsx` 约 75 行、`src/rail.tsx` 约 19 行）：现在英文包也要单独下载，`loadLocale` 的 catch 里 `await loadLocalePack("en")` 再失败就直接抛出，`Promise.all(...).then(render)` 没有 catch，页面永远不渲染。改成：英文也失败时照常渲染一个带「重试」按钮的最小错误页（文案用一份很小的内置英文，样式沿用 PageBoundary / ScreenUnavailable），点重试重新加载。补测试：en 也失败时出现重试页、点重试成功后正常渲染。`src/lib/i18n.test.ts` 约 259 行把离线 mock 改成 `offline && tag !== "en"` 是在回避这条路径，改回能覆盖 en 失败。
2. **开发/e2e 预览入口一渲染就抛错**：`src/locales/index.ts` 的 `en` 初始为空、`t()` 取不到会抛 `Locale not ready`；`src/computer-ask-preview.tsx`、`src/onboarding-preview.tsx`、`src/mascot-preview.tsx` 和 `scripts/testing/` 下 22 个 `*-preview.tsx` 只调同步 `setLocale("en")` 或不加载语言。加一个小的预览引导模块（例如 `src/testing/preview-locale.ts`：`await loadLocale(...)` 后再渲染），所有预览入口统一先用它；用 `grep -rln 'createRoot' src scripts/testing` 之类找全入口，逐个确认。
3. **AttachmentGallery 改回真正的 Markdown 解析**（`src/components/AttachmentGallery.tsx` 约 25–58 行）：正则版和服务端授权解析（`server/message-file.ts` 用 `fromMarkdown` + `windowsPathDestinations`）不一致，15 个用例里 9 个结果不同（括号路径、反转义、自动链接、引用式链接、嵌套方括号、缩进代码、HTML 注释、转义方括号），而且 ChatMarkdown 本来就静态引入了 `mdast-util-from-markdown`，体积零收益。恢复 `fromMarkdown(text, { mdastExtensions: [windowsPathDestinations] })`；拆到 `chat-markdown-links.ts` 的 `localFilePath` 可以保留。加一个测试，用上面那几类用例对比确认客户端与 `shared/markdown-windows-paths.ts` 的结果一致。
4. **生产 manifest 里有构建机绝对路径**（`scripts/locale-bundles.ts` 约 15 行、`vite.config.ts` 约 59 行）：虚拟模块 id 是 `\0locale-bundle:<绝对路径>.json.js`，`dist/.vite/manifest.json` 里有 48 处构建机绝对路径，而静态文件服务可能把它公开出去。把虚拟 id 改成相对形式（如 `\0locale-bundle:zh`）；`vite.config.ts` 不再默认开 `manifest: true`，体积检查脚本自己用 `vite build --manifest` 生成（或在 `check:bundle` 里先构建再检查），并确认 `dist/` 里任何文件都不含构建机路径（`grep -r "$PWD" dist` 为空）。
5. **撤回收益可以忽略的小懒加载**（`src/components/lazy-screens.tsx`）：LiveCallHost（约 0.5K gzip）、NewBotName（约 1.2K）、ConversationShareDialogs（约 1.5K）、TeamWelcome（约 1.5K）、FirstConversationTour（约 1.3K）改回静态 import；CloudWelcome、CloudSetup、CloudIntent 是云端首次进入的主界面，fallback 不能为 null——体积小于 3K gzip 的改回静态，大的给 Loader2 占位。`lazy-screens.test.ts` 同步。
