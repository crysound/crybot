## 必改
1. **CloudSetup 的占位把所有人的界面压到半屏（`src/components/lazy-screens.tsx:362-364`，配合 `src/App.tsx:427`）。**
   `<CloudSetup>` 是 App 最外层 `flex h-full flex-col` 的直接子节点，对所有用户无条件挂载（非云端时返回 null）。本轮给它加的 `flex flex-1` Loader2 占位在块加载完之前和主界面各占一半高度，本地用户也一样；块加载失败时所有人还会看到 ScreenUnavailable。
   改法：CloudSetup 改回静态 import（只有约 3.8K gzip）。`lazy-screens.test.ts` 里对应用例一起改。CloudWelcome 的占位在主内容区，保持不动。
2. **3 个开发验证脚本漏了语言包（r3 第 2 条没找全）。**
   `scripts/verify-server-connection.mjs:303-310`、`scripts/verify-company-backups.mjs:444-447`、`scripts/verify-organization-settings.mjs:283-289` 用 `createServer({ configFile: false, plugins: [...] })` 自建 vite，没挂 `localeBundles()`，内联入口同步 `setLocale('en')` 就渲染，结果 `virtual:english-contracts` 解析失败、页面打不开。
   改法：三处 plugins 加 `localeBundles()`，内联入口先 `await` 语言包（`loadLocale('en')` 或 `preparePreviewLocale`）再渲染。再全仓搜一遍 `createRoot(` 和 `createServer(`（不要只搜 `src`、`scripts/testing`），确认没有别的漏网入口，搜索命令和结果写进报告。`preview-locale.test.ts` 的入口扫描覆盖 `scripts/` 根目录（或在报告说明为什么不覆盖）。

## 顺手做（都很小）

4. `src/components/lazy-screens.tsx:369` 的 CloudEngineSignIn 是云端首次进入时主内容区的界面，fallback 现在是 null。改回静态 import（约 3.9K），与 CloudSetup 一致。
