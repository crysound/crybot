## 必改

1. **登录后整页崩溃**：`src/App.tsx` 约 304 行用到 `<HomeLine />`，但 import 被删了，也没从 lazy-screens 导入 → 运行时 `ReferenceError: HomeLine is not defined`，PageBoundary 显示“页面出错”。`src/App.engine-status.test.ts` 两项失败就是它。恢复静态 import。
2. **vendor-markdown 把 Markdown 和 KaTeX 拉回首屏**：`vite.config.ts` 的 manualChunks 把 mdast/micromark/remark/hast/unified/react-markdown 归成一个块，而 `src/components/AttachmentGallery.tsx` 静态用到 `mdast-util-from-markdown`，结果 App 静态 import 整个 vendor-markdown（约 135KB gzip），KaTeX 也从 main 上的独立懒加载块被并了进来（回归）。去掉 markdown 这组 manualChunks；ChatMarkdown 保持**静态**（和 main 一样），只让 KaTeX、mermaid、shiki 等重扩展维持懒加载。`AttachmentGallery` 的 fromMarkdown 若确实只在少数场景用，改成动态加载。用构建产物确认：App 块不再静态 import 它们，`katex-*.js` 仍是独立懒加载块。
3. **撤回无收益、有副作用的懒加载**：
   - `LazyChatMarkdown` 去掉（消息正文首帧为空、布局跳动、N 条消息叠 N 个错误提示）。所有用到它的地方（ChatView、CallSheet、DataCard、InboxReading、WidgetNodes、GroupView 等）改回静态 ChatMarkdown。
   - `src/components/lazy-screens.tsx` 新加的 NotificationRail、NewLocalFromMenu、CommandPalette、CryBotWelcome、EngineSetup 在产物里都没有独立块（仍被静态引用），撤回，恢复原来的静态 import。ChatView 的 EngineSetup 恢复静态（“Sign in to Claude” 按钮首帧要在）。
   - 保留确有独立块且收益明确的（例如 GroupView）；GroupView 加载中要有占位（沿用 App.tsx 现有的 Loader2 那种），不能整块主内容为空。
   - `lazy-screens.test.ts` 的约定（SCREENS 预加载列表）要和最终实现一致，测试全绿。
4. **语言包（本轮主要的瘦身点）**：`src/locales/index.ts` 静态 import `en.json`（约 191KB gzip），所有用户都下载；中文用户再加 zh（约 157KB gzip）。zh 比 en 少约 2,594 个 key，不能直接去掉 en。做法：构建时为每种语言生成「本语言 + 缺失 key 用英文补齐」的合并包，按当前语言**只动态加载一个包**；英文用户只加载 en。首次渲染前把语言包加载好（不要出现先英文后中文的闪烁、也不要出现 key 原文）；加载失败退回英文包。切换语言时按需加载新包。保持现有 i18n 测试通过（`src/lib/i18n.test.ts` 里 pt-br 缺 3 个 key 那 1 项是 main 已有失败，不能新增失败）。不加依赖，用现有 vite 能力或一个小的构建插件/脚本实现。
5. **体积检查脚本口径**：`scripts/check-frontend-budget.mjs` 要统计「入口 + 登录后立即加载的 App 块及其全部静态 import 闭包 + 当前语言包（按 zh 计，取最大的一个也可）」，用 `build.manifest` 或解析产物 import 图实现；一个资源都没匹配到时报错退出；阈值常量保留 `500 * 1024`，口径写进注释；常量和检查逻辑分开（或加 main 判断），被 import 时不触发检查。在 `package.json` 加一个脚本（例如 `check:bundle`）运行它；**不改 `.github/`**，接入 CI 由协调者做。现阶段若仍超 500KB，脚本允许通过 `--report-only` 只打印不失败，并在报告里写清。
6. **删掉 `vite.config.ts` 里写 /tmp 的 moduleStats 统计插件**。
7. **报告如实重写**：用 gzip -9 口径列 main 与改后各块（入口、vendor-*、App、语言包、ChatMarkdown 首条消息块），给「入口」「登录后机器人列表+普通聊天（英文用户）」「同上（中文用户）」三个合计，写清离 500KB 还差多少、下一步最值得拆的是什么（审核建议：shared/carved-bodies.ts、ProviderIcons.tsx、AttachmentPreview.tsx、tailwind-merge、首屏是否真的需要 tldts 与 zod）。不要夸大。
