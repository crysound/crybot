# T-1231-mac-island 第 3 轮返工：截图脚本在 CI 上卡死

原任务说明 `docs/tasks/T-1200/T-1231-mac-island/brief.md`、第 2 轮 `r2.md`，先读。第 2 轮代码审核已通过，本轮**只修截图脚本**，产品代码不动（除非查明卡死原因在产品代码里，届时在报告里写清楚）。

## 现象
Actions「macOS island screenshots」连续 3 次被取消：`pnpm exec electron scripts/testing/island-screenshots.mjs` 这一步启动后**没有任何输出**，约 18 分钟后撞上作业 `timeout-minutes: 20` 被取消，随后 upload-artifact 因没有 png 报错。前面的 vite build、`node --test electron/island*.node-test.mjs`、`vitest run src/island/Island.test.ts` 都通过。

脚本里 `waitFor` 有 15 秒超时，但下面这些调用没有超时，任何一个不返回都会无声卡死：`app.whenReady()`、`win.webContents.executeJavaScript(...)`（页面没加载完或渲染进程挂起时）、`win.webContents.capturePage()`（窗口隐藏/不可见/未绘制时在 macOS 上可能永不返回，第一张就是 `hidden` 模式）。另外 `render-process-gone` 里 throw 不会被外层 try 捕获。

## 必改
1. **全局看门狗**：脚本启动即设一个总超时（如 4 分钟），到点打印「卡在哪一步」并 `app.exit(1)`；作业不得再靠 20 分钟作业超时结束。
2. **每一步打日志并限时**：whenReady、创建岛窗口、页面加载完成、每次 executeJavaScript、每次 capturePage 前后都打一行进度；这些调用用 Promise.race 包一个单步超时（如 20 秒），超时抛出带步骤名的错误。
3. **查明并修掉卡死的真正原因**，让截图在 macos-26 上真的产出。重点排查：
   - 页面是否真的加载（在加载完成/失败事件上打日志，`did-fail-load` 要报错）；
   - 隐藏状态下 `capturePage` 是否返回：对不可见窗口截图时，先用 `showInactive()` 或设置 `paintWhenInitiallyHidden`/`backgroundThrottling:false` 等让它绘制；hidden 模式若窗口本身不可见，可改为截取一张能说明「平时不显示」的画面（如窗口尺寸为 0 或透明时记录状态并截全屏区域），在报告里说明取舍；
   - 无头 CI 上 Electron 是否需要额外启动参数（如 `--disable-gpu`）。
   在报告里写明根因和依据（日志行）。
4. `render-process-gone`、`did-fail-load`、`unresponsive` 改为记录错误并让脚本以非零退出，不在事件回调里 throw。
5. 工作流里截图这一步加 `timeout-minutes: 8`，作业总超时保留 20。
