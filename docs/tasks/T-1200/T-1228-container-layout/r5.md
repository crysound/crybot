r4 的 websockify 由 root 监护再降权（复审实测降权彻底、信号转发无可利用点）、重启后重取端口、podman 标记探测都通过，vitest container-screens 22/22、container-computer 149/149、container-mcp 13/13。Actions「Real VM screens」（head f9f2b30e）在 usercustomize 正向对照失败：

```
Error: docker exited 1: stat: cannot statx '/tmp/crybot-usercustomize-s2': No such file or directory
    at ... scripts/smoke-screens-container.mjs:36:33
```

复审查明根因（r4 说明的写法有误，不是开发的错）：
- 基础镜像 PATH 以 `/opt/venv/bin` 开头，`python3` 实际是 venv 里的 Python 3.13；该 venv 未开 `include-system-site-packages`，启动时 ENABLE_USER_SITE 为 False，不执行 usercustomize，所以 :206 不产生标记，:207 必然失败。
- 即使正向对照能过，钩子写进的是 venv 3.13 对应的 user site，而 `screen-process` 的 shebang 是 `/usr/bin/python3`（Debian 系统 Python，版本可能不同），目录对不上，防护失效时 :217 也不会变红。
- 监护进程实际的 HOME 来自镜像的 `HOME=/home/cua`，不是 s2 的 HOME，现在的反向断言只在「去掉 `-I`」和「HOME 换成 s2」同时发生时才会变红。

## 必改
1. **usercustomize 冒烟改用正确的解释器**（`scripts/smoke-screens-container.mjs:204-207,217`）：
   - :204 取 user site 目录、:206 正向对照，都显式用 `/usr/bin/python3`（与 `screen-process` shebang 同一个解释器），先在冒烟里打印该解释器版本。
   - 正向对照：s2 身份用 `/usr/bin/python3 -c pass` 后断言标记出现且属主 61002。
   - 新增直接测 `-I` 的反向对照：以 root、`HOME=/home/crybot-s2` 运行 `/usr/local/libexec/crybot/screen-process crybot-s2 true`（按实际路径和参数），断言标记不存在或不属 root。这样只去掉 `-I` 这一项就会变红。保留原有重启屏后的反向断言。
   - 在报告里写明：把 `screen-process` 的 `-I` 临时去掉时，新反向对照会失败（本地用等价的纯 Python 脚本或单测演示即可，写明方法）。
2. **root 的 supervisord / supervisorctl 会加载 cua 的 user site**（`server/container-screens.ts:239`；`server/container-computer.ts:1088,1090,1100,1130`；冒烟脚本 :42；多屏初始化脚本里 `exec supervisord` 处）：镜像 `HOME=/home/cua`，容器以 root 运行时继承这个 HOME，Debian 的 supervisord/supervisorctl 是不带 `-I` 的 python3 脚本，会加载 cua 可写的 `/home/cua/.local/lib/python3.X/site-packages` 下的 usercustomize.py 和 .pth。cua 一旦能执行代码，下次服务端以 root 调 startScreen/stopScreen/screenStates 就会以 root 执行它的代码。改为：
   - 初始化脚本 `exec supervisord` 前设 `HOME=/root PYTHONNOUSERSITE=1`；
   - 所有 `exec -u 0 ... env -u VNC_PW ...` 调用加上 `HOME=/root PYTHONNOUSERSITE=1`（集中在一个帮助函数里，不要逐处复制）；crybot-pkg 以 root 跑 apt 的路径同样处理。
   - 单测断言这些调用带上了这两个环境变量；冒烟加一条：以 cua 身份在 `/home/cua` 的 user site（用 `/usr/bin/python3` 取目录）放 usercustomize 写标记，然后 root 调一次 supervisorctl status，断言标记不存在或不属 root；结束清理。
