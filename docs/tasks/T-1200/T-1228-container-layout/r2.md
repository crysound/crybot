## 必改
1. **独立的 supervisord 配置**（container-screens.ts:109-121）：生成一份新的 supervisord 配置文件，只含 `[supervisord]`、`[unix_http_server]`、`[rpcinterface:supervisor]`、`[supervisorctl]` 段，加上各屏的屏幕组和令牌模式 websockify，然后 `exec env -u VNC_PW supervisord -c <新配置>`。原镜像的 dbus、vncserver :1、novnc、crybot-cua-driver 在多屏布局下都不启动（规格第 4 节）。测试断言这份配置不含 vncserver、novnc、crybot-cua-driver，并含 4 个屏幕组。
2. **websockify**（container-screens.ts:114）：去掉位置目标参数 `127.0.0.1:5901`，只用 `--token-plugin`；以 `user=cua` 运行，不用 root。
3. **VNC 口令文件格式**（container-computer.ts:1037-1043 `startScreen`）：在容器内用 `vncpasswd -f` 从标准输入生成 rfbauth 文件，属主为该屏用户、权限 0400；口令先校验非空、长度至少 8（不满足直接报错，不启动）。口令不出现在命令行参数和日志里。
4. **运行目录权限**（container-screens.ts:104）：先单独 `install -d -o U -g U -m 0700 /run/user/$uid`，再建其下的 tmp；测试断言两级目录都有。
5. **oom_score_adj**（container-screens.ts:106）：不要把 uid 当 PID。改为每个屏 supervisor 程序的命令前加 `choom -n 500 --`（镜像没有 choom 时用 `sh -c 'echo 500 >/proc/self/oom_score_adj; exec ...'`），不要 `|| true` 吞错。
6. **每用户进程数上限**（container-screens.ts:92）：去掉 dash 不支持的 `ulimit -u`。给每个屏程序和屏内 exec 单独加 `prlimit --nproc=1500 --`。
7. **屏内 exec 程序错位**（container-computer.ts:1197-1201、:562）：把「身份和环境」与「执行哪个程序」拆开（例如新增 `screenIdentityArgs`），exec 路径不再插入 `CUA_EXECUTABLE`；补回归测试断言 exec 的完整参数。
8. **`-w` 插入位置错**（container-computer.ts:538）：非屏目标、`interactive` 为 false 时生成了 `exec -u -w /w cua ...`。改为按 `-u` 的位置插入或直接构造参数；补回归测试。
9. **屏目标的 exec 去掉 VNC_PW**（container-computer.ts:531-565、container-mcp.ts:22-24）：屏目标的所有 exec（MCP、命令执行、状态探测、截图）统一包一层 `env -u VNC_PW`；补测试断言。
10. **用户 ID 迁移与 `GUEST_IDS_SCRIPT` 共用**（container-screens.ts:72-80）：在 server/container-isolation.ts 导出不带 exec 的脚本主体（或一个前缀函数），单屏、多屏两种布局共用，不要自己重写。保留原脚本的做法：只改 gid 时不 chown（避免清 set-id 位和文件能力）、单独处理绑定挂载的 `/home/cua/workspace`、最后 `id` 校验失败就 `exit 1`。单屏布局生成的参数必须与改动前完全一致（用完整相等断言锁住）。
11. **探测不到时判 single**（container-screens.ts:81-82、container-computer.ts:866）：Apple container 运行时先不打 `com.crybot.screens-layout=multi` 标签；Docker 下初始化脚本回退到单屏时写一个标记文件，`screensLayoutOf`（或状态探测）读到标记就判为 single。补测试。
12. **`screenStates` 解析**（container-computer.ts:1051-1064）：supervisorctl 退出码 3 时从错误对象里取 stdout 照常解析；按屏汇总（任一 FATAL/BACKOFF/EXITED 为 failed；全部 RUNNING 为 running；有 STARTING 为 starting；STOPPING 为 stopping；全部 STOPPED 为 off）；执行本身失败（docker 出错、超时）时抛错，不要返回 `{}`。补测试。
13. **屏目标不污染状态缓存**（container-status-cache.ts:28-29、container-computer.ts:699-706）：屏目标只复用容器级探测，自己不去探屏套接字；返回给调用方时把 `target_key` 改写成该屏的 key。缓存键的判断统一用 `containerTargetOf`/`isScreenTarget`，不要再有第三套写法。补测试：停着的 s3 先被查询，不影响 s2 截图。
