## 必改
1. **root 监护进程可被屏幕用户注入代码**（`server/container-screens.ts:110` 的 `#!/usr/bin/python3`，配合 :32 给 root 程序设 `HOME=/home/crybot-sN`）：root 运行的 Python 会加载 HOME 下的 user site（`usercustomize.py`、`.pth`），屏幕用户放一个文件再杀掉自己的 Xvnc，supervisor 重启时即以容器 root 执行。改为：shebang 用 `#!/usr/bin/python3 -I`；HOME/USER/XDG_RUNTIME_DIR 等屏用户环境不放进 root 进程的 supervisor `environment=`，改在子进程 setuid 之后设置。补测试断言 shebang 带 `-I`、root 程序段环境里没有屏用户 HOME；冒烟加一项：s2 在自己 HOME 写 usercustomize（写一个标记文件到 /tmp），重启 s2 后确认标记文件不存在或不属 root。
2. **运行目录符号链接提权**（`container-screens.ts:212` `install -d -o crybot-sN ... /run/user/$uid/tmp`）：`/run/user/$uid` 归屏幕用户，可把 `tmp` 换成指向任意目录的链接，容器重启时 root 的 install 会跟随链接 chown/chmod 目标。改为：初始化时先 `rm -rf /run/user/$uid`（运行目录不该跨启动保留），再两级 install；并排查脚本里其余以 root 操作屏幕用户可控路径的语句，同样处理（先删再建，或 `[ -L ]` 判定）。补测试断言重建前先删除；冒烟加一项：s2 把 `/run/user/<uid>/tmp` 换成指向一个 root 目录的链接，重启容器后该目录属主不变。
3. **标记探测失败污染整个状态**（`server/container-computer.ts:675-679`）：多屏标记的 root exec 探测在 docker inspect 的大 try 里、且排在 network/imageMatches/managed/security/persistence 赋值之前，exec 失败会被 `catch {}` 吞掉，这些字段全落成默认值，用户被提示重建容器。改为：标记探测挪到这些赋值之后，单独 try/catch；失败时写 desktop_error 或保持屏未就绪，不影响容器级字段。补「标记探测抛错」测试：容器级字段照常、只有屏状态未就绪。
